# Plan: Herdr 칸반 플러그인 (herdr-plugin)

**작성일**: 2026-09-03
**대상**: `herdr-plugin/` (신규), 백엔드 무수정
**복잡도**: High

## 요약

칸반 보드를 Herdr 터미널 안에서 직접 조작할 수 있는 TUI 플러그인을 만든다.
기존 `mcp-server/` 가 **AI 에이전트용 창구**라면, 이 플러그인은 **사람용 창구**다.
따라서 조회에 그치지 않고 생성·수정·삭제·댓글까지 전체 CRUD 를 지원한다.

백엔드 API 는 이미 필요한 표면을 모두 갖추고 있어 **서버 코드는 수정하지 않는다.**

## 배경 — 이미 있는 것

| 자산 | 내용 |
|------|------|
| API Key 인증 | `ApiKeyAuthFilter`, `ApiKeyService` — `Authorization: Bearer ak_...` |
| REST API | 일감·상태·하위일감·댓글·보고 엔드포인트 전부 존재 |
| MCP 서버 | `@dksktjdrhks2/kanban-mcp@1.2.1` (npm 발행 완료), 도구 16종 |
| SSE | `SseController` — 실시간 변경 알림 |
| 참고 구현 | herdr-sidebar(Rust), herdr-grid(Rust, 드래그 앤 드롭 실증) |

## 범위

**포함**: 칸반 보드 표시, 일감 CRUD, 하위 일감, 댓글, 상태 변경, 프로젝트 전환,
검색·필터, 실시간 갱신, 키보드 + 마우스(드래그 앤 드롭 포함) 조작.

**제외**: 첨부파일 업로드·다운로드, 대시보드 통계, 프로젝트 생성·설정, 사용자 관리.
이들은 웹 UI 가 담당한다. 업무보고 생성은 MCP 도구가 이미 제공한다.

## 아키텍처

플러그인 식별자는 `herdr-kanban` 으로 고정한다.
저장소명(`ysk-kanban`)이나 디렉토리명(`herdr-plugin`)과 구별되며,
`herdr plugin list` 와 설정 디렉토리 경로에 이 값이 쓰인다.

```
kanban-board/
├── mcp-server/                 (기존, 무수정)
└── herdr-plugin/               (신규, plugin id = herdr-kanban)
    ├── herdr-plugin.toml
    ├── package.json
    └── src/
        ├── cli.js              진입점 — 설정 로드, Ink 렌더, 종료 처리
        ├── api/client.js       REST 클라이언트 (인증·오류·재시도)
        ├── api/sse.js          실시간 갱신 구독 + 폴링 강등
        ├── config.js           설정 파일 로드·저장
        ├── store.js            상태 관리 (보드·선택·모달·낙관적 갱신)
        ├── layout.js           좌표 계산기 (렌더·히트 판정의 단일 출처)
        ├── input/keys.js       키 입력 처리
        ├── input/mouse.js      마우스 이벤트 처리 + 드래그 상태 기계
        ├── input/hit.js        좌표에서 대상을 판정
        └── ui/                 Board, Column, Card, Detail, Form, Palette, Help
```

### MCP 서버와 코드를 공유하지 않는다

API 클라이언트가 겹치지만 공유 패키지를 두지 않는다.
공유하면 두 쪽 배포가 묶여 npm 발행 때마다 양쪽을 함께 올려야 한다.
클라이언트는 200줄 남짓이라 **중복 비용보다 결합 비용이 크다.**

### 폭에 따른 적응

| pane 폭 | 동작 |
|---------|------|
| 140열 이상 | 보드 + 상세 패널 병렬 표시 |
| 90~139열 | 상세 패널 숨김, `Enter` 로 전체 화면 상세 |
| 90열 미만 | 목록 모드 — 칸 배치를 포기하고 상태를 왼쪽 색 막대로 표시 |

칸이 화면보다 많으면 `h`/`l` 로 가로 스크롤한다.
칸 색상은 `ProjectStatus.color` 의 16진값을 트루컬러로 그대로 쓴다.

## 조작 체계

### 설계 원칙

1. vim 계열 키를 기본으로 하되 화살표·`Enter`·`Esc` 도 항상 받는다.
2. 되돌릴 수 없는 조작은 반드시 확인 단계를 거친다.
3. Herdr prefix 키와 충돌하지 않도록 단일 키만 쓴다.

### 키맵

| 키 | 동작 |
|----|------|
| `j` `k` / 아래·위 화살표 | 칸 안에서 카드 이동 |
| `h` `l` / 왼쪽·오른쪽 화살표 | 칸 사이 이동 |
| `g` `G` | 칸의 첫 카드 / 마지막 카드 |
| `Tab` | 보드와 상세 패널 사이 포커스 전환 |
| `Enter` | 상세 열기 |
| `/` | 제목 검색 (증분 필터) |
| `f` | 필터 (우선순위·담당자·마감 임박) |
| `p` | 프로젝트 전환 팝업 |
| `r` | 새로고침 |
| `m` | 마우스 캡처 토글 (터미널 텍스트 선택 복구용) |
| `?` | 도움말 |
| `q` | 종료 (`Esc` 는 모달만 닫음) |
| `n` | 새 일감 (현재 칸에 생성) |
| `s` | 하위 일감 생성 |
| `e` | 수정 (팝업 폼) |
| `E` | 설명을 `$EDITOR` 로 편집 |
| `Space` | 상태 변경 (칸 선택 팝업) |
| `H` `L` | 인접 칸으로 즉시 이동 |
| `c` | 댓글 추가 |
| `x` | 삭제 (확인 필수) |

`dd` 같은 연속 키 대신 `x` + 확인창을 쓴다. Ink 에서 연속 키는 오입력에 취약하다.

### 입력 화면

팝업 폼으로 처리한다. 제목·우선순위·마감일·담당자를 `Tab` 으로 오가며 채운다.
설명은 최대 2000자의 여러 줄이므로 `$EDITOR` 에 위임한다.
임시 파일을 만들어 에디터를 띄우고, 저장 후 읽어 반영한다.

### 상태 변경의 두 갈래

백엔드는 단순 이동과 완료 처리를 구분한다.
완료 칸으로 옮기면 `completedAt` 기록과 하위 일감 자동 완료가 함께 일어난다.

따라서 완료 칸을 고르면 미완료 하위 일감을 먼저 확인하고,
있으면 "하위 N건이 미완료입니다. 함께 완료할까요?" 를 묻는다.
MCP 서버의 `complete_todo` 와 동일한 규칙이므로 두 창구의 행동이 일치한다.

## 좌표 체계와 드래그

### Ink 의 자동 레이아웃을 쓰지 않는다

드래그하려면 화면의 특정 좌표에 어떤 카드가 있는지 알아야 하는데,
Ink 의 Flexbox 는 계산 결과를 밖으로 내주지 않는다.
따라서 레이아웃을 직접 계산하고 그 결과로 렌더링과 히트 판정을 모두 수행한다.

```
layout.js   pane 크기 + 칸 구성 + 스크롤 위치 + 접힘 상태
              -> [{ kind:'card', id:1902, x:2, y:5, w:16, h:5 }, ...]
                        |                         |
                        v                         v
                 ui/Board.jsx              input/hit.js
                 (좌표대로 그림)        (좌표로 대상 판정)
```

계산 결과가 그리기와 판정의 **단일 출처**이므로 보이는 것과 눌리는 것이 어긋날 수 없다.
herdr-grid 의 `Geometry::hit(column, row)` 와 같은 구조다.

### 마우스 조작

| 조작 | 동작 |
|------|------|
| 클릭 | 카드 선택 |
| 더블클릭 | 상세 열기 |
| 드래그 | 카드를 다른 칸으로 이동 |
| 휠 | 칸 안 스크롤 |
| 칸 머리 클릭 | 칸 접기·펼치기 |
| 상단 프로젝트명 클릭 | 프로젝트 전환 팝업 |

드래그는 누름·이동·뗌 3단계 상태 기계로 처리한다.
누른 카드를 들어 올려 표시하고, 커서가 지나는 칸을 강조하며,
뗀 위치의 칸으로 상태 변경을 요청한다. 칸 밖에서 떼면 취소한다.
완료 칸에 떨어뜨렸을 때의 하위 일감 확인은 키보드와 동일하다.

### 마우스 캡처의 대가

마우스를 잡으면 터미널 기본 드래그 선택·복사가 막힌다.
대부분의 터미널이 `Shift` + 드래그를 자체 처리하므로 그 경로는 살아 있고,
추가로 `m` 키로 캡처를 껐다 켤 수 있게 한다.

Herdr 는 pane 앱이 요청하면 마우스 이벤트를 전달한다.
기본 설정 주석에 다음과 같이 명시되어 있다.

> Pane apps like lazygit and btop can still receive mouse when they request it.

Ink 는 마우스를 기본 지원하지 않는다.
**먼저 `@ink-tools/ink-mouse`(peer `ink >=6`) 로 시도하고,
Herdr pane 에서 이벤트가 도착하지 않으면 SGR 마우스 프로토콜을 직접 구현한다.**

직접 구현할 경우의 범위는 다음과 같다. 활성화 시퀀스를 stdout 에 쓰고,
stdin 으로 들어오는 `CSI < 버튼 ; 열 ; 행 M`(누름) 과 `m`(뗌) 을 파싱하며,
종료 시 반드시 비활성화 시퀀스를 보내 터미널 상태를 되돌린다.
비정상 종료로 마우스 모드가 남으면 터미널이 먹통이 되므로
`process.on('exit')` 과 시그널 처리에 정리 코드를 반드시 건다.

## 보안 고려사항

### 1. API Key 의 프로젝트 바인딩이 실질적으로 무력하다

`TodoController.resolveProjectId()` 는 요청 파라미터를 키 바인딩보다 우선한다.

```java
private Long resolveProjectId(Long projectId, HttpServletRequest request) {
    if (projectId != null) return projectId;              // 요청이 우선
    Object apiKeyProjectId = request.getAttribute(...);   // 없을 때만 키의 프로젝트
    return null;
}
```

`GET /api/projects` 도 키의 프로젝트가 아니라 **그 계정의 전체 프로젝트**를 반환한다.

**이 플러그인은 이 동작에 기대어 프로젝트 전환을 구현한다.**
덕분에 백엔드 수정이 필요 없지만,
`docs/plan/mcp-api-key-integration.md` 가 명시한
"키는 특정 프로젝트에 바인딩" 이라는 의도와는 어긋난다.

이 불일치를 어떻게 처리할지는 **별도 판단이 필요하다.**
바인딩을 실제로 강제하면 이 플러그인의 프로젝트 전환이 깨지므로,
그때는 계정 단위 키(`projectId = null`)를 별도로 도입해야 한다.

### 2. API Key 가 평문으로 저장된다

OS 자격증명 저장소를 쓰면 네이티브 모듈이 필요해져
컴파일이 없다는 Node.js 의 이점이 사라진다.
기존 `.mcp.json` 도 평문으로 키를 담고 있어 일관성은 있으나,
**이 파일이 유출되면 계정의 모든 프로젝트가 노출된다.**

## 데이터 흐름과 오류 처리

기동 시 다음을 순서대로 받는다.

1. `GET /api/projects` — 프로젝트 목록
2. `GET /api/statuses?projectId=` — 칸 구성
3. `GET /api/todos?projectId=` — 카드

이후 갱신은 SSE 구독으로 밀어 받고, **끊기면 30초 폴링으로 자동 강등**한다.
상단에 연결 상태를 표시해 사용자가 지금 실시간인지 알 수 있게 한다.

쓰기는 **낙관적 갱신**으로 처리한다. 화면에 먼저 반영하고 요청을 보내되,
실패하면 원래 상태로 되돌리고 하단에 오류를 한 줄 띄우며
해당 카드에 잠깐 빨간 테두리를 남겨 어떤 항목이 실패했는지 찾을 수 있게 한다.

## 검증 계획 (구현 1단계에서 먼저 확인)

| 확인 항목 | 실패 시 대응 |
|-----------|--------------|
| Windows 에서 `[[panes]]` 로 node 프로세스가 뜨는가 | herdr-sidebar 방식(`pane split` 후 명령 입력)으로 전환 |
| Herdr pane 에서 마우스 이벤트가 도착하는가 | 키보드 전용으로 축소하고 재논의 |
| conpty 환경에서 트루컬러가 나오는가 | 256색 근사 팔레트로 대체 |

**알려진 함정** (herdr-sidebar 의 `CLAUDE.md` 에서 확인):

- Windows 에서 `[[panes]]` 의 **상대경로** 명령은 실행되지 않는다 (herdrdev/herdr#3024).
  `npx` 와 `node` 는 PATH 상의 명령이라 해당하지 않을 가능성이 높으나 확인이 필요하다.
- action id 는 플랫폼 간에도 전역 유일해야 한다. Windows 변형은 `-windows` 접미사를 붙인다.
- herdr pane 의 셸은 사용자 설정에 따라 다르다. PowerShell 의 `&` 호출이나
  sh 의 `exec` 를 타이핑하지 말고 PATH 를 조작해 명령 이름만 쓴다.
- Windows pane 은 PowerShell 5.1 일 수 있다. `&&` 대신 `;` 나 `if ($?)` 를 쓴다.
- 문서에는 `[[actions]]` 의 `contexts` 가 필수라고 되어 있으나 실제로 쓰는 플러그인이 없다.
  문서와 구현이 어긋난 것이므로 넣지 않는다.

## 테스트 전략

가장 틀리기 쉬운 두 곳에 무게를 싣는다.

| 대상 | 방식 |
|------|------|
| `layout.js` 좌표 계산 | 순수 함수 단위 테스트 — 폭·칸수·스크롤 조합별 좌표 검증 |
| `input/hit.js` 히트 판정 | 경계 좌표를 포함한 단위 테스트 |
| `store.js` 낙관적 갱신 | 성공·실패 경로와 롤백 정확성 |
| `api/client.js` | 응답 모킹, 인증 실패와 네트워크 오류 처리 |
| `ui/*` | `ink-testing-library` 로 렌더 결과 확인 |

목표 커버리지는 80% 이상이다.

## 배포

개발 중에는 `herdr plugin link .` 로 로컬 등록해 쓴다.
완성 후에는 다음으로 설치한다.

```
herdr plugin install world-goes-to-hell/ysk-kanban/herdr-plugin
```

herdr-sidebar 도 같은 모노레포 구조(`plugins/herdr-sidebar`)를 쓰므로 검증된 패턴이다.
Node.js 라 컴파일이 없어 build 단계는 `npm ci --omit=dev` 한 줄이면 된다.

## 결정 기록

| 결정 | 이유 |
|------|------|
| 전체 CRUD | MCP 는 에이전트용, 플러그인은 사람용. 사람이 쓸 때는 모든 기능이 동작해야 한다 |
| Node.js + Ink | MCP 서버와 같은 언어, npm 발행 경험 재사용, 크로스컴파일 문제 없음 |
| 웹 화면이 아닌 TUI 재구성 | Windows conpty 가 Sixel·Kitty 그래픽 프로토콜을 차단한다 |
| 모노레포 배치 | 기존 저장소와 발행 파이프라인 재사용, herdr-sidebar 가 같은 패턴 |
| MCP 와 코드 미공유 | 결합 비용이 중복 비용보다 크다 (클라이언트 200줄) |
| 수동 레이아웃 계산 | 드래그에 좌표가 필요한데 Ink Flexbox 는 좌표를 내주지 않는다 |
| `$EDITOR` 위임 | 2000자 여러 줄 편집을 TUI 안에 만들면 구현량 대비 이득이 적다 |
| 드래그 앤 드롭 포함 | 웹과 같은 조작감. herdr-grid 가 같은 환경에서 실증했다 |
